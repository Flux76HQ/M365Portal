## 2. Mutation pass over the runner and the corpus

Method: a copy of `apps/server` in the scratchpad (workspace `node_modules` linked), one edit per run, only `hostile-uploads.test.ts` without the red block, a green baseline first; a mutant counts as killed when the run fails. Three passes, about 65 distinct mutants: the guards of the runner (outcome, leftover files, markers, connections, audit, budget, PNG chunk walk, output shape), the structural guards of the corpus (coverage, row match, markers, determinism), the PNG helpers (CRC, padding, the bomb's final block, remainder and Adler-32), the generators (H-18, H-24, H-28, H-35, H-39, H-41, H-42), the listener, `defineFixture` and `write-hostile.ts`.

First pass: 28 mutants, 20 killed (two of the eight others were strings that did not match the formatted source and were rewritten). Second pass (43 mutants, including the survivors of the first): 36 killed. The mutants that survived (six in the first pass, seven in the second, some of them the same) were each a real gap in the tests and were closed with tests: a non-square image for the edge limit and for the size check, a negative where only the stored files (not the output PNG) hold the marker, a marker only in the audit text, a marker in the database files, a crash that must not be taken for a rejection, the audit table of `expectedAudit`, the three "opening verb" checks of the row match (codes right, shape wrong), UTF-16 big endian without a trailing character, and the primary payload of a row. Third pass: those survivors again, plus one string that had not matched: 7 of 7 killed. In the final state no mutant survives; none is known to be equivalent.

Not covered by mutation: the exact payload text of most SVG fixtures. They are checked by their markers being present, by being well-formed (or not) for libxml2, by the structural pins listed in section 1 and by the Appendix A row match; an edit that makes a payload harmless while keeping its marker would not fail a test. The sanitiser tests (`T-A-079`, `T-A-080`) are the control for that.

## 3. Interfaces the next tasks use

Fixture shape (`apps/server/test/fixtures/hostile/types.ts`): `{ id, category, summary, markers, fileMarkers, inputs, prepare(context), bytes(context?), expected }`. Deviations from the task text `{ id, bytes(), expected, markers[] }`: `bytes()` is **async** (sharp is), takes an optional `HostileContext { listenerOrigin, workDir }`, and returns the first input; `expected` is the list of the outcomes of all inputs, because several rows are more than one file (H-18 has 3, H-33 has 8, H-38 has 5, H-42 has 11). `fileMarkers` is the content of files a payload tries to read (it is not in the input but must not appear in any stored or served byte). Input kinds: `upload` (bytes, claimed file name and media type, slot, optional `layer: 'image' | 'http'`, optional `transport` plan), `import`, `assetGet`, `orgName`, `burst`.

Outcome vocabulary: `accepted` (exact `warnings`, optional `optionalWarnings`, `categories` as a lower bound, optional `size` and colour `probes`), `rejected` (a problem code; status from the registry), `status` (408, 413, 404 without a registry code), `oneOf`, `cutOff`, `burst`, `storedAsText`. "Neutralised" is `accepted` with `svg_content_removed`. A guard (`assertFixtureMatchesRow`) keeps every fixture equal to its Appendix A row: the codes it names (plus `svg_content_removed` for "Neutralised" and `image_processing_timeout` for "terminated within the time budget"), and whether the row begins "Neutralised", "Accepted" or "Rejected". Changing a row of the spec fails the corpus until the generator follows (spec first).

Runner (`apps/server/test/branding/hostile-harness.ts`):

- `runFixture({ fixture, target, environment })` runs every input a target supports and asserts, per input: the outcome within 5 s (`FIXTURE_BUDGET_MS`), a clean stored PNG (`assertCleanPng`: only `IHDR PLTE tRNS IDAT IEND pHYs`, no bytes after IEND, valid CRCs, at most 512 or 128 pixels) and its size and colours (`assertOutputShape`), the audit entries (`assertAudit`, only for an audited target); per fixture: nothing left in the private temporary directory or `branding/.tmp`, no marker or file marker in any stored or served byte or text, zero connections at the local listener.
- `createWorkspace()` makes a private root and sets `TMPDIR` to a directory inside it while it is open, so "nothing left in /tmp" is exact and does not see the temporary files of other test processes. Create it **before** other helpers that call `tmpdir()`, or those directories count as leftovers.
- `viaPipeline(subject)` where `PipelineSubject { process({ bytes, slot }) => Promise<{ png, warnings: { code, categories? }[] }>; maxRunning?(); close?() }`. A rejection must be an `Error` with a problem `code` that the registry knows; any other error fails the run (a crash is not a rejection). It runs the inputs with `layer !== 'http'` and the burst.
- `viaHttp({ server, publicOrigin, csrfToken, dataDir, readAudit, serverFor? })`: real requests over a socket (`sendRaw`, which sends request targets exactly as written, chunked or with `Content-Length`, with aborts and slow bodies), a hand-written multipart body (so hostile file names reach the server as written), reads the stored images back through `GET /branding/<hash>.png`, scans `dataDir`, `dataDir/branding` and `.tmp` for markers. `serverFor(plan)` must return a server with `requestTimeout` and `connectionsCheckingInterval` from the plan (H-37).

## 5. Assumptions

- The external references of the payloads (`<image href>`, `@import`, `xml-stylesheet`, an external entity, `<iframe src>`) point at `context.listenerOrigin`, the 127.0.0.1 listener of the run, not at `https://attacker.example` as the appendix writes it: a connection to a non-existent host cannot be seen. `write-hostile.ts` uses `https://attacker.example` by default, with `--listener <origin>` for an owner who wants to watch a socket.
- Hostile imports (H-42) are built from a valid document `{schemaVersion: 1, orgName, accent, images: {logoLight, logoDark, compact}}` with one mutation each. "A media type that does not match the bytes" is read as a `data:image/...;base64,` prefix in front of a PNG's base64 (the schema wants canonical base64 and nothing else), once with `image/jpeg` and once with `image/svg+xml`.
- H-38 uses the percent-encoded forms `%00`, `%0d%0a` in file names. A raw CR LF in a quoted file name breaks the multipart framing (plan V-06: it fails to parse), so it is not "ignored" and is not in the row's set; the Node/undici parser decodes `%0d%0a` and `%22` in `File.name` (the HTTP stand-in test pins that, so the server really sees a CR LF) and leaves `%00` as text.
- H-43 has the names the row lists plus `registry-miss` (a well-formed hash that is not registered) and an upper-case `.PNG`. Other path tricks (`%2e%2e/`, `..%5c`, `/branding/.tmp/<hash>`) were left out: they have more than one path segment, where the SPA fallback decides before the asset route, and the row does not list them.
- H-39 expects at least 6 of 20 to be accepted (2 running plus 4 queued always fit) and every refusal to be `image_processing_busy`; it does not demand that any request is refused, because a fast pipeline may admit more.
- The colour probes of H-40 (45 per channel for the CMYK file, 30 for the sRGB-like profile) come from sharp's own conversion (CMYK blue 210 became 177); a pipeline without a CMYK profile may differ and then the tolerance is changed with evidence, not silently.
- The `TMPDIR` switch of `createWorkspace()` is per process. Vitest runs one test file per process here, so other files are not affected; a run with `--no-isolate` would share it.

## 6. Risks

- **Red block in a shared suite.** See s2b-1. It also costs about 14 s of the server package's test time on a free machine (the corpus is regenerated for the determinism, marker and stand-in tests; H-35, H-36 and H-42 are 2, 4 and 9 MB each).
- **Real-time test.** H-37 takes about 1.1 s of real time (a body sent 16 bytes per 50 ms to a server with a 1 s `requestTimeout` and a 100 ms check interval); Node's default check interval is 30 s, which is why the plan carries `serverCheckIntervalMs`. A loaded machine can only make the 408 come later, and the runner's 5 s budget leaves room. The file sets `vi.setConfig({ testTimeout: 60000 })`.
- **Stand-ins are not the application.** Everything the runner proves, it proves against stand-ins (a stub pipeline, a Hono app, a plain Node server). That the runner is wired correctly to the real pipeline and the real routes is only known when `T-A-083` and `T-A-093` make the red block green; until then the adapters' glue code for the real objects (`createPipelineSubject`, `serverFor`, `readAudit`) is unproven.
- **Hand-built formats.** The HEIC fixture is a hand-built `ftyp` plus `meta` box (the prebuilt sharp has no HEVC encoder), enough for a magic-byte sniffer and not decodable; the PDF is a minimal file with a JavaScript action. AVIF, GIF, WebP and TIFF are real files from sharp.
- **sharp output is part of the bytes.** The raster fixtures that sharp encodes (the base JPEGs, the CMYK file, GIF, WebP, AVIF, TIFF) are deterministic for the pinned version; a sharp upgrade may change their bytes (never their meaning), and the pins above (sizes, orientation, colours) would say if it changed the meaning.
- **Metadata calibration only.** The claim "sharp opens none of the 42 SVG inputs (H-19 left out) without making a connection" is measured with `metadata()`, which parses the file but does not render it; the rendering claim (FR-A-088, H-04, H-05, H-08) is `T-A-081`'s test.
