## 14. Assumptions and risks

- **R1. Port literals in e2e helpers** (decision 5). Confirmed by a plant this round.
- **R2. Luminance in the image pipeline** (decision 6). Confirmed by a plant this round; the guard also reacts to function names, not only constants.
- **R3. Names of homes are pinned by the single-implementation table** (section 11). If S3 picks contrast helper names outside the six listed, or S1 or S4 spell a pinned name differently, the test is red until S0 extends the table; ask early.
- **R4. Positive proof arrives later.** Every home is an `export {};` stub today, so "green on the scaffold" proves that nothing is defined twice and that the detector works (proven per name with synthetic homes and by the plants above). Since round 2 a home that holds code must define its pinned names, which makes the guard positive as soon as an owner writes the first line.
- **R5. Accepted trade-off** (W2): an unanchored hex extractor outside `packages/shared` is not seen by `single-implementation.test.ts`. Review and accept, or tighten.
- **R6. FR-A-008 is read from the spec.** One test reads the `| FR-A-008 |` row and fails if it stops mentioning one of its eight concepts; rewording that row needs the table updated in the same commit.
- **R7. Everything in `packages/shared/src` that the exports map exposes is compiled twice** by `exports.test.ts`, under NodeNext (node types) and under bundler resolution (DOM, no node types). Shared source must stay platform-neutral and compile in both; a file that does `import 'node:fs'` fails this test even if the server accepts it (shown by plant).
- **R8. Other guard scopes to remember.** Check 4 scans every text file of `apps/web/src` (hex, colour functions in any case, named colours in colour places, Tailwind arbitrary values, palette utilities; block comments excepted); check 6 covers CSS, HTML, `@apply`, class strings and style objects of `apps/web`; check 2 resolves the whole `extends` chain of every tsconfig, tests included, and rejects switching off any `strict`-family flag; check 3 also covers `overrides`, `resolutions`, the last `save-exact` of `.npmrc` and a `.gitignore` that would hide the lockfile; check 8 fails on a source file above 1,000,000 characters; check 9 fails on a test file nobody collects; check 10 forbids switching off a local lint rule.
- **R9. The scans walk the filesystem, not git.** `packages/shared/test/support/repository.ts` skips `node_modules`, `.git`, `.worktrees` at the root and build output (`dist`, `coverage`, `playwright-report`, `test-results`, `blob-report`, `.vite`, `.turbo`) directly inside a package root. A stray copy of the repository, a package-local `.pnpm-store` or other scratch directory inside the tree would be scanned and can produce findings or oversize failures. The gate ran with `dist` and `e2e/test-results` present and was green.
- **R10. Assumption**: "a clean checkout" means a copy of the tracked and untracked files plus `.git`, with a warm or a cold pnpm store reached over the sandbox proxy. A GitHub runner was not exercised.
