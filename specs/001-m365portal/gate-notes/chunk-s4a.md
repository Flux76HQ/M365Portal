## Assumptions

- A-1 English is the source catalogue and the fall back of every lookup; `en` and `nl` are the only locales (`LOCALES`), so the fragment languages are exactly those two.
- A-2 A message is resolved plain key first, then the plural form for `params.count`, then `.other`, in the locale's catalogue and then in English (with English plural rules for the English text); a key found nowhere is returned as it is. Silent in production by design: an unknown key must never crash a page.
- A-3 A catalogue is flat JSON of dotted keys, `{name}` placeholders (letters, digits, underscore) and no escaping for a literal brace: braces are reserved, and the catalogue check reports a brace that is not a well-formed placeholder.
- A-4 Key parity compares a plural group as one key, because the forms per language differ (Arabic has six, English two). Missing forms are the plural check's job.
- A-5 The script of a catalogue is the script with the most letters; Latin is always allowed; a catalogue dominated by Han or Hangul also keeps its second non-Latin script (Latin brand names do not take a slot). Placeholders are not read as language.
- A-6 Scripts the list in `catalogue-check.ts` does not name count as one script, `Other`. The list has 43 scripts.
- A-7 `detectLocale` recognises only the two-letter primary subtags `nl` and `en`, case-insensitive, with `-` or `_` as separator; `nld`, `eng`, `x-nl` and `*` are not guessed at.

## Risks

- **R-1 The checks' blind spots are real** (stated in the header of `i18n-catalogue.test.ts` and executable as two tests): one Latin-script language filed as another (nl and en are both Latin, so on the catalogues of this repository the third-script check can only pass; the fixtures are what prove it works), and a catalogue that shifted wholesale (its own script is inferred from itself). Review of translations stays a human task.
- **R-2 A Japanese catalogue would be judged too strictly.** Han-dominant keeps two non-Latin scripts; kanji, hiragana and katakana are three. No such catalogue exists or is planned; whoever adds one decides what the rule becomes (the header says so).
- **R-3 `Intl` data.** `t`, `n` and `d` rely on the ICU data of the runtime. Chromium 141 and Node 22 (full ICU) were exercised; the distroless Node of the image was not asked about `nl` (the server does not format with it in Phase A).
- **R-4 Import attributes.** `with { type: 'json' }` in `create-translator.ts` was verified with `tsc` (NodeNext and bundler), Vitest, `tsx`, esbuild 0.28.2 and Vite 8.3.4 in a scratch project; a tool that does not know import attributes would fail on it. `import type` of the same file must not carry attributes (TS 6 rejects it), and does not.
- **R-5 Generated catalogues conflict.** Parallel branches that both add keys produce a textual conflict in `locales/{en,nl}.json` even when the fragments merge cleanly (see s4a-2). The fragments are the source; the generated files are regenerated.
