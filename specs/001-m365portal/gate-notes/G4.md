## 3. D-3: user text inside a sentence

An organisation name is typed text and can be right to left. As plain text in "Appearance of {name}" it reorders the neighbouring neutral characters (E-07). `lib/isolate.tsx` `isolatedMessage(t, key, params, { name })` builds the sentence as nodes with the value inside a `<bdi>`: private-use markers stand in for the value while `t()` fills the catalogue sentence, then the markers are replaced by `<bdi>{value}</bdi>` (a value cannot forge a marker: it never passes through the catalogue's interpolation). Used for `appearance.object` (the Reset dialog and the unsaved-changes dialog: `ConfirmDialog` got an optional `objectContent` node next to the required string `objectName`, so the required-name contract and its type tests are unchanged), `preview.summary` (a `<bdi>` in the sentence) and `preview.paneLabel` (an attribute cannot hold an element: the group is labelled through `aria-labelledby` on a hidden element built with the helper, the accessible name is the same text). The document title and the actor label are not changed: the title is the browser's own text, and the actor label in Phase A is a catalogue word (`shell.actor.preview`), not user text; a Phase B display name needs the same helper (OP-5).

**What the spike found** (the probe had measured a skeleton at 2.1 to 2.6 s; the real shell measured 3.5 s):
1. The first paint waited for the JavaScript. The simulated mobile network (1.6 Mbit/s, 150 ms round trip, 4x CPU) needs about 1.4 s for the 209 KB of Brotli JavaScript alone, and Lighthouse's simulation includes every request that finished before the observed first paint in the paint it estimates (that is what the runs show: with the script requested in the head, even a static shell did not help, the step "+ static shell" has FCP still at 2.8 s).
2. Only a static LCP candidate that stays the largest element helps, and only if the application's files are not fetched before the first paint. In preview mode that element is the preview banner, which the server knows and the HTML can carry.
3. Total Blocking Time was the second problem: the 4x throttled phone turned three real tasks of 25 to 56 ms into 340 to 430 ms of blocking time (the module graph evaluated in one task, the first render committed in one task, `cn` compiling its tables at start-up for 150 ms throttled, zod 60 to 100 ms throttled).
4. Not worth it: removing the font preload (LCP 3.56 and 3.61 s against 3.50 to 3.55 s); kept (FR-A-123).

**Decision for `T-A-173` (how much of tactics 5 to 7 is needed)**: tactic 5 (static shell) is needed and is built; tactic 6 was already in place and verified; tactic 7 (a server-rendered page heading chosen from the language) is **not** applied: it would not reach the default instance without the static page also knowing the actor's permissions (a wrong "no access" flash for a signed-in administrator in Phase B), and the preview instance passes without it. The shell, the deferred start and the short-task start-up are what moved the numbers.

## 8. Frozen interfaces

Unchanged and reviewed (JSDoc matches behaviour): `lib/api` (`createApiClient`, `ApiError`, `NetworkError`, `shouldRetry`, `UpdateSignal`; the only `fetch` caller, the loader uses `import()`), `lib/storage` (`STORAGE_KEYS`, `createStorage`, `getAppStorage`, never throws), the command registry (`COMMANDS`, `visibleCommands`, `navigationCommands`).

New, frozen for S5, S8 and S9:
- **HTML template (C8)**: the six placeholders still occur once each (the nonce on every tag). `#root` holds the static shell. The document has no module script and no `modulepreload`; `<script type="application/json" id="m365-start" nonce>` holds `{ "entry", "preload": [...], "routes": { "/path": [...] } }` (URL paths of build files) and is the contract for tooling (`scripts/bundle-budget.ts`, `test/build-output.test.ts`, `e2e/tests/headers.spec.ts`). Three inline classic scripts, in this order: the boot script (theme, language), the static shell's script, the loader. The server needs no change.
- **Static shell**: `[data-slot=static-shell]` (hidden until its script), `[data-shell-lang=en|nl]`, `[data-shell-banner]`, `[data-shell-org]`; text only through `{en:key}` and `{nl:key}` tokens (a missing key fails the build); keys in use `banner.preview.title`, `banner.preview.message`. A page that wants its own static content later adds to this block and to the catalogue check, never a literal string.
- **Start-up**: `main.tsx` stages, `boot/stage-{react,data,router,ui}.ts` are what the plugin preloads (by module name), `boot/yield.ts`, `router.load()` before the first render, the first render a transition.
- **`lib/cn.ts`** is `createCn(tables)` from `cn/engine`; the theme's utility names live in `lib/cn-config.ts`; `lib/cn-tables.generated.ts` is written by the build (committed, byte-compared by `test/ui/cn-tables.test.ts`): add a utility to the config or a new class family to the sources and run the build, then commit the file.
- **`lib/isolate.tsx`**: user text in a translated sentence goes through `isolatedMessage`; an attribute uses `aria-labelledby`.
- **`components/pages/staged.tsx`** (`StagedRoot`, `Staged`): a long page mounts in parts and says `data-progressive="pending"|"done"`. `e2e/fixtures.ts` `app.ready()` waits for `main` and for no `pending`.
- **Route files**: a route that needs lazy code before it renders puts it in its `loader` (Appearance does).
