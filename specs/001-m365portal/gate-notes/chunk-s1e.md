## 4. Interfaces the next tasks use

Everything is in `apps/server/src/http/route.ts` unless named. JSDoc of C4 to C7 is for `T-A-046` to review.

- `defineRoute({ id, method, path, access, rateLimit, audit?, summary?, description?, tags?, bodyLimit?, request?, responses, handler })` returns a frozen `RouteDefinition`; nothing is registered until the application is built. `access` is `{ public: true }` or `{ permission }` (a type error otherwise). `rateLimit` is `read | write | upload | exempt`. `request` is the `request` of `@hono/zod-openapi` (`params`, `query`, `headers`, `body.content`); the handler gets `(c, input)` with `input.params`, `query`, `headers`, `body` typed from the schemas. A media type declared with a plain OpenAPI schema (not Zod) is documentation only and is not validated: that is how S2 declares the multipart upload and reads `await c.req.formData()` itself. Paths use `{name}`; header schemas need lower-case keys (`if-match`). The handler returns a `Response` (`c.json(...)`, `c.text(...)`); the declared `responses` are documentation, not checked at run time.
- `defineFallback({ id, methods, paths, access, rateLimit, openapi: false, handler })`: the handler returns a `Response` or `undefined` to decline. `rateLimit` may also be `'by-method'` (the class of the request's method).
- `createHttpApp(deps)` returns `{ app, table, document }`. Deps: `config` (the fields of `AppConfig` listed in `HttpAppConfig`), `routes`, `fallbacks?`, `csrf`, `limiter`, `log` (`debug info warn error`), `now?` (ms), `onDenied?`, `onStorageFailure?`, `openApi { version, title?, source? }`. It builds the whole pipeline of plan 7.2 in order (request context, security headers, actor, request log, compression, cache rules, OPTIONS rate and refusal, error boundary), registers every route with its guards, appends the 404/405 fallback, checks the table (`assertRouteTable`), the router against the table (`assertRouterMatchesTable`) and the document against both (`assertOpenApiParity`), and fills `openApi.source`. Any mismatch throws a `RouteTableError` and nothing is returned. `T-A-045`'s `buildApp(deps)` is this call plus the construction of its arguments.
- Guards of a route, in order: rate limit (the declared class), body limit (`bodyLimit` or the JSON class, the upload class for a multipart body) and content type (writes only), Origin plus CSRF (`originAndCsrfGuard`, writes) or `auditedReadGuard` (a GET with `audit`), authorisation (`authorize` for a route with a permission). A denial of Origin, CSRF or authorisation on a write goes to `onDenied(c, { code, reason, route: { id, method, path (the template), permission? } })` before the response exists; if the hook throws, the error handler answers (fail closed).
- `route-table.ts`: `validateRouteTable`, `assertRouteTable`, `RouteTable` (`routes`, `fallbacks`, `allowFor(path)`), `RouteTableError`, `registeredRoutesOf(app)`, `checkRouterAgainstTable`, `assertRouterMatchesTable`. `openapi.ts`: `buildOpenApiDocument`, `checkOpenApiParity`, `assertOpenApiParity`, `createDocumentSource`, `OpenApiDocument`.
- `denial-audit.ts`: `createDenialAudit({ database: () => DatabaseHandle | undefined, now })` gives the `onDenied` hook. `database` returning `undefined` (degraded mode) is a 503 `storage_unavailable`. The entry: `action` = route id, `outcome = denied`, `reasonCode` = `permission_denied | origin_not_allowed | csrf_invalid`, actor, request id, client address, detail `{ method, route (template), permission? }`.
- `routes/health.ts`: `healthRoutes({ version, readiness })` with `interface Readiness { check(): ReadinessResult | Promise<ReadinessResult> }` (`T-A-044` implements it, with the 2-second cache; the route asks it on every request and keeps nothing). `routes/meta.ts`: `metaRoutes({ version, publicOrigin, showcase, storageAvailable: () => boolean, csrf, binding?, document })`. `routes/robots.ts`: `robotsRoutes()`.
- `http/static.ts`: `staticFallback({ root })` (`static.assets`: `/assets/*` and `/offline.{html,css,js}`, exempt), `serviceWorkerRoute({ root })` (`pwa.serviceWorker`, a documented route), `isServablePath`. `http/spa-fallback.ts`: `spaFallback({ shell })` (`shell.html`), `isShellRequest`. `shell-port.ts`: `ShellRenderer`, `createPlaceholderShell(template)`, `readShellTemplate(webRoot)`, `ShellTemplateError`, `NONCE_PLACEHOLDER`. The fallbacks go in this order: `[staticFallback, spaFallback]`; `fallback.notFound` is appended by `createHttpApp`.
- `AppVariables.actor` is set by the pipeline from `createActorResolver(config)`.
- The table-driven tests. `policy.test.ts` and `audit-integration.test.ts` iterate over `writeRoutesOf(app)` (`test/helpers/http-app.ts`), which reads the write routes from the table and the document of an application. Today `app` is the fixture application. **When `buildApp` exists (`T-A-045`) and the branding module is registered (`T-A-092`), the same two tests must also run over the table of the real application** (build it with `createTestApp` and pass the real `buildApp`); the helper only needs `http.table` and `http.document`. `ALLOWED_PUBLIC_WRITES` in `policy.test.ts` is empty for the real table on purpose: a public write route is added there deliberately or the test fails.

## 5. Assumptions and decisions

1. **The boot rules go beyond FR-A-031.** The table check also refuses a write route outside `/api/v1`, a write route whose id is not an audit action (lower case words: the id is the `action` of its denial entries), a rate class that does not fit the method (a write in `read`, a GET in `upload`), a fallback that is documented, and a route that is not. S2's ids and classes in contract section 2 all satisfy them (`branding.asset.stage` is `upload`, `branding.import` is `upload`, `branding.export` is a `read` GET with `audit`).
2. **Rate limiting is per route, not global.** Each route and fallback carries its class as its first guard; an unmatched path is rated by method through `fallback.notFound` (`by-method`), and OPTIONS is rated before it is refused. This keeps "rate limit first" without a lookup of the route table on every request.
3. **405 is computed from the table.** A path that matches the pattern of a route under another method answers 405 with `Allow` (HEAD with GET, sorted); fallbacks do not count, so `POST /assets/x.js` and `POST /` are 404. The contract says "known path, wrong method"; the shell and the static files are not routes.
4. **The placeholder shell fills the nonce and nothing else.** C6 says "nonce only, default title" and the test line of `T-A-043` says "fills only `__M365_NONCE__`"; I followed the test. The other five placeholders of C8 stay literal until S2's renderer replaces the renderer. The nonce is validated (standard base64, at least 22 characters) because it is written into attributes unescaped.
5. **Static files are an allow-list, not a blacklist.** A path is served only if every segment matches `[A-Za-z0-9_-][A-Za-z0-9._-]*` (no leading dot), the last has an extension and is not `index.html`, and the file is a regular file whose real path is inside the root. The build output has no file that needs more; a future file name with `@` or `+` is a 404 until the grammar is widened on purpose. `static.assets` serves only `/assets/*` and the three offline files; any other file-like path (`/favicon.ico`, `/x.png`) is a 404 problem, never the shell.
6. **The shell needs an explicit `text/html` in `Accept`** (weight above 0). `*/*`, a missing header or `application/json` get the 404 problem. A browser navigation sends `text/html`; `fetch` and curl do not.
7. **`serveStatic` stays**, with a `Vary: Accept-Encoding` added for a plain file that has a Brotli or gzip sibling (the library adds it only when it picks a sibling). The library matches `Accept-Encoding` tokens exactly, so `br;q=1` is not matched and the plain file is served (and then compressed by the compression layer): correct, a little less efficient.
8. **`/sw.js` is a documented route (`pwa.serviceWorker`, R17)**, `/assets/*` and the offline files a fallback, as the contract's index says. Its worker profile and `no-cache` with an ETag come from the pipeline by path.
9. **A denial hook failure is a 5xx**, never the denial: a storage error (read-only, busy, no database) is 503, an invalid entry (a bug) is a 500 `internal_error`. The audit is written in a transaction of its own, so a denial never shares a transaction with a change.
10. **`ReadinessResult` is read-only** (`status`, `checks[]`), the shape of `ReadyzResponse`; the route returns 200 for `ready` and 503 otherwise and does not catch a throwing readiness (a 500, logged without the message). The readiness implementation is expected never to throw for a failing check.

## 7. Risks

- R1. **Hono and the router.** The parity checks read `app.routes` (one entry per handler; `ALL` is middleware) and rely on Hono 4.13 recording method-specific registrations that way. A Hono upgrade is covered by `route-table.test.ts` and `openapi.test.ts`, which go red if the reading breaks.
- R2. **`@hono/zod-openapi` mediaTypeGate.** For a declared JSON or form body the library adds its own 415 gate after our content-type guard and validators of its own; with our guards first, its gate is only reached by a request our guard already accepted. A library upgrade that changes the order of validators and `route.middleware` would break the fixed order; `route-table.test.ts` (the matrix) is the control.
- R3. **No browser run.** The shell, the nonce and the worker profile are asserted with in-process requests and `node:http`; `T-A-322` (e2e) is the control for a browser, as for the headers.
- R4. **Public write routes.** Nothing forbids a public write route (Phase B has `/setup`); the table-driven test lists the allowed ones. Until Phase B the list is empty, which is what FR-A-033 says.
- R5. **Fixture binaries.** `test/fixtures/web-dist/assets/*.br` and `*.gz` are generated bytes committed as fixtures (the test decompresses them and compares with the source file); they are not regenerated by any script.
