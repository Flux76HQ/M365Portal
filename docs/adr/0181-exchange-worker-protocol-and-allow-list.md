# ADR-0181: The Exchange worker speaks a closed line protocol and may call ten cmdlets

Samenvatting (NL): De server praat met één langlevende `pwsh`-worker via regelgebonden JSON op stdin en stdout (versie 1, één aanroep tegelijk, met deadline, gesloten foutcodes zonder vrije tekst). De worker mag tien cmdlets en niets anders; de toegestane lijst staat op één plek in `packages/shared`, wordt twee keer gecontroleerd (server en script) en het script draagt de SHA-256 ervan. Het formaat van de certificaatoverdracht (`connect`) is besloten (PEM) maar nog in aanbouw.

## Status

Plan. **Superseded in part by ADR-0182 (2026-10-14): the line protocol and the `pwsh` worker are gone; the closed allow-list of ten cmdlets (decision 2 onward) is still in force and is what `InvokeExchangeClient` sends.** Decided in the Phase D spec (FR-D-101 to FR-D-105, FR-D-107) and the plan (sections 4.1 and 5.1), frozen at gate GD1-0 (T-D-105) and adjusted while building (gate notes GD1-server-a and GD1-server-b; the rows below are what the code does). One part is **not finished**: the shape of the `connect` certificate (decision 7). Nothing here has run against a real Microsoft 365 tenant.

Source: `specs/004-phase-d/spec.md` FR-D-102, FR-D-103, FR-D-104, FR-D-105, FR-D-107, `research-microsoft-d.md` R-D-01 to R-D-03 and R-D-09, ADR-0180 (the image that holds the worker), ADR-0102 (the Exchange port is an interface; the owner chose the worker, ODB-01 A).

## Context

Exchange Online cannot be written through Microsoft Graph, and the documented way is the `ExchangeOnlineManagement` module on PowerShell 7 (R-D-02, R-D-03). Three things make this the riskiest seam of the product:

1. **Input becomes a command.** The panel puts administrator-typed text (a search prefix, a display name, an address) into cmdlet parameters. If any of it can reach the command text, or select another cmdlet or parameter, the panel is a remote shell for an application that holds the Exchange Administrator role.
2. **Learn warns about silent breadth.** `Get-MailContact -Identity $null` and an unknown identity "return all objects" (R-D-09); a destructive cmdlet waits for a confirmation prompt that nobody can answer; `Member` is optional in the syntax of `Add-` and `Remove-DistributionGroupMember` although it is required in practice.
3. **The process is long-lived and talks a lot.** The module prints to the console, a PowerShell error text can hold a name or an address (FR-D-107), repeated connect and disconnect can leak memory (R-D-03), and a call can hang.

## Decision

1. **One worker, one line protocol.** The server starts one `pwsh` child at the first Exchange call, with `spawn` and an argument list (no shell), a fixed script, and an environment of a short list of names (the proxy and certificate-bundle variables of the parent, plus its own fixed ones; never `APP_KEY` or the like). It speaks version 1 of a protocol of **one JSON object per line** on stdin and stdout (`packages/shared/src/exchange/protocol.ts`): a request is `connect`, `call`, `ping` or `shutdown`, with a request id; a `call` carries `{ cmdlet, args, deadlineMs }` (1,000 to 120,000 ms); a response is `{ v, id, ok: true, data }` or `{ v, id, ok: false, error: { code, retryAfterMs? } }`. Requests are **serial**. A line is at most `exchange.lineMaxBytes` (1,048,576); a longer answer is cut and marked `truncated`, and the client never shows a cut list as complete (a list that large is refused as `too_many_rows`). Framing is tested at every split point of a chunk, and an overflowing line is dropped, not parsed.
2. **Closed error codes, no free text.** The worker answers with one of `not_found`, `already_exists`, `already_member`, `not_a_member`, `member_type_not_allowed`, `permission_denied`, `manager_check`, `read_only_object`, `throttled`, `timeout`, `invalid_argument`, `not_connected`, `role_pending`, `internal`. The script maps an exception to a code by its fully qualified error id first and its text second; anything it cannot place is `internal`, **never a guess at success**. A message from Exchange never leaves the worker. The server turns a code into a problem code (`exchange_unavailable`, `exchange_throttled`, `exchange_permission_missing`, `read_only_object`, per-member reasons).
3. **Stdout is for the protocol only.** The script redirects the console and information streams to null and writes protocol lines through its own writer; the Node side ignores a line that is not protocol JSON and never logs it, and **stderr is discarded**. The server logs the request id, the cmdlet name, the outcome and the duration, and nothing else (FR-D-107).
4. **A closed allow-list, ten cmdlets, validated twice.** `packages/shared/src/exchange/allow-list.ts` is the single source: `Get-DistributionGroup`, `Get-DistributionGroupMember`, `Add-DistributionGroupMember`, `Remove-DistributionGroupMember`, `Get-MailContact`, `New-MailContact`, `Set-MailContact`, `Remove-MailContact`, `Get-Recipient`, `Get-OrganizationConfig`. Each has parameters of a **kind** (text with a pattern and a maximum length, switch, boolean, result size, enumerated value or list, identifier list), required parameters, an "at least one of" rule (`Set-MailContact`) and a `confirmFalse` flag. An unknown parameter, a prototype trick (`__proto__`, inherited names), an `undefined` value or a value outside its pattern is refused, and a refusal names parameters, never values. The same table is **generated into the script** (`exchange:check` fails when the generated block differs), together with its SHA-256; the worker reports the hash at connect and the server stops a worker whose hash differs. The server checks before it writes the line; the script checks again before it runs the cmdlet.
5. **Rules the table encodes.** (a) Arguments are bound as **named parameters** by splatting (`& $command @parameters`); no `Invoke-Expression`, no script block from input; the module is loaded with `-CommandName` for the allowed cmdlets only (`-SkipLoadingFormatData`). (b) **`Confirm` and `WhatIf` are never a caller parameter**; the script adds `-Confirm:$false` itself on the two `Remove-` cmdlets (`confirmFalse`). (c) **An `Identity` is required, non-blank and never `undefined`** for every cmdlet that has one (R-D-09). (d) `Member` is required on `Add-` and `Remove-`. (e) Values of the fields that go into a filter are single-quoted literals with every quote doubled, and a search prefix may not hold a wildcard (the only wildcard is the suffix the code appends). (f) `Set-MailContact` has no first or last name (R-D-09, U15); `Set-Contact` is not on the list.
6. **Lifetime.** A call has a deadline of `exchange.callDeadlineSeconds` (120); the worker is killed at it and started again. It is recycled after `exchange.workerMaxCalls` (500) calls or `exchange.workerMaxAgeSeconds` (3,600) seconds. Throttled and transient answers are retried at most `exchange.retryMax` (3) times with a doubling wait (1 s to 15 s, jitter, `Retry-After` first); the numbers are ours until U81 is closed. A worker that dies at any step is replaced; a request does not wait for a dead one.
7. **The certificate hand-over (`connect`).** The `connect` line carries the application id, the organisation and the certificate; `EXCHANGE_KEY_HANDOVER=memory` (default) sends it over the pipe and builds the certificate object in memory, `tmpfs` is the fallback (a mode 0600 file on a tmpfs, removed after the connect; refused when the directory is not a tmpfs). **The shape of the certificate was the one decision the protocol left open** (GD1-0): the first contract carried a PKCS#12 (`pfx-base64` and a password), which Phase B cannot produce (it seals a PKCS#8 key and keeps the public certificate; Node cannot write PKCS#12) and which would need a new direct dependency. **Decided by the owner on 2026-10-13: PEM** (`certificate` and `privateKey` as PEM text, the script builds the object with `X509Certificate2.CreateFromPem`, no password). The amendment of `protocol.ts`, `key-handover.ts` and the script, and the narrow audited method that hands the key to the hand-over once and zeroes it (a change to the secrets module), are **in progress**; until they land every Exchange route answers 503 `exchange_unavailable`. Whether the module accepts an in-memory certificate on Linux at all is U75, closed only by OV-D1.

## Consequences

- **Closed on purpose.** A new cmdlet or parameter is a change to one file in `packages/shared`, its tests and a regenerated script; it cannot be added from a route. `Get-DynamicDistributionGroupMember` is not on the list, so a dynamic list has no member list in D1 (finding FD-05); adding it is a change to `packages/shared`.
- **Not a sandbox.** The worker runs as the same user in the same container as the server. The allow-list and the pipes are what keep administrator input from becoming code; there is no kernel boundary (see `docs/security.md`). A seccomp profile or a second container (ODB-01 B) would add one and was not chosen for D1.
- **A list that is too large is refused, not cut.** With a 1 MiB line the member read of a list fails as `too_many_rows` at about 2,500 members (AD-02 assumed a few thousand); a larger line or a smaller projection is a later decision. A result above 10,000 rows (`exchange.listBufferMax`) is 422 `narrow_search`.
- **Slow first call.** The worker starts at the first Exchange call; the `pwsh` start and the module import are paid then. Unmeasured (U84).
- **Parameter value lists are partly unverified:** `SortBy` of `Get-DistributionGroup` and the `RecipientTypeDetails` values of `Get-DistributionGroup` and `Get-Recipient` are identifier patterns, not enumerations (U99); the error-to-code mapping and the text of "already a member" and "not a member" answers are our reading (U94, U100). Each falls back to `internal` or to a failed member, never to success.
- **The Exchange layer is testable without Exchange.** The server tests run the real `PwshExchangeClient` over a stand-in process that speaks the same protocol (`standin-process.mjs`) and over a strict fake tenant; the real script ran on a real PowerShell 7 only for the protocol, the allow-list and the hand-over file, never against a tenant.

## Evidence

- `packages/shared/test/exchange-allow-list.test.ts` (closed map, prototype tricks, unknown parameter, empty identity, the manifest changes when the table changes), `exchange-protocol.test.ts` (framing at every split point, overflow, closed error codes, an allow-list bypass attempt on the wire; negative: a parser that skips the allow-list lets a forbidden request through), `exports.test.ts`.
- `apps/server/test/exchange/worker-protocol.test.ts`, `worker-lifecycle.test.ts` (deadline kill, recycling by calls and age, a crash at every step, the serial queue), `allow-list.test.ts` (the hash and the script scan), `retry.test.ts`, `no-personal-data-in-logs.test.ts`, `key-handover.test.ts`, `no-key-on-disk.test.ts` and `node-launcher.test.ts` (environment, arguments, no shell, no secret on the command line).
- `apps/server/test/exchange/real-pwsh.test.ts` ran the real script on PowerShell 7 (10 tests; skipped where `pwsh` is missing). It never talks to a tenant.
- Not verified here: the module on Linux against a real tenant (U75 to U77, U83 to U85), the error texts and ids the script maps (U94, U100), and the credential source (finding FD-01). They are the owner test `docs/owner-test-phase-d1.md`.
